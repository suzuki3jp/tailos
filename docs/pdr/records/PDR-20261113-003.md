# 長い返答は同じ会話で Agent に要約を再要求する

## 決定

保存上限を超えたユーザー向け返答は、機械的に切り捨てず、その旨を Agent に返して同じ会話で短く書き直してもらう。再要求は最大 2 回とし、Run の残り時間を確認する。要点・前提・質問・検証結果の整合性を保持して要約するよう求める。Codex に渡す outputSchema の reply から minLength / maxLength を外し、長さは Runner 側で検証する。

## 理由

末尾の質問・前提・検証結果を機械的に欠落させず、Agent 自身が意味を保って短縮するため。再要求回数を制限して無限のやり直しを防ぐ。モデル向けスキーマの未検証の長さ制約を既存の実装経路へ広げない。

## 範囲と例外

ログだけでなく、Session に保存・表示する返答本文の扱いである。8,000 という閾値そのものの根拠はこの決定では承認していない。実装成果の保持と具体的な秒数は別の未確認記録を参照する。PR #54 の採択方針であり、この作業ツリーにその実装が存在することを意味しない。

## 選択肢と影響

無条件の切り捨てでは、ユーザーが内容の欠落を認識できない。即座に失敗させるだけでは、調査結果を返せない。再要求には追加の推論時間が必要で、期限を考慮する必要がある。
