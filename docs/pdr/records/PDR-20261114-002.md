# Claude 接続は長期 OAuth トークンの貼り付けだけを対象にする

## 決定

Claude の接続は、利用者が手元で `claude setup-token` を実行して得た長期 OAuth トークンを Web の接続画面に貼り付ける方式だけを提供する。API キーでの接続は当面作らない。

## 理由

Claude Code には、ChatGPT 接続で使っているデバイスコード認証のように外部サービスが駆動できるログインも、外部からアクセストークンを更新する仕組みもない。対話なしの実行で使える資格情報は、API キーと `claude setup-token` の長期 OAuth トークンの二つである。

現在の Tailos は運用者が自分のデプロイで自分のために使っており、契約済みのサブスクリプションで実行できることを優先する。長期 OAuth トークンは CI やスクリプトでの利用が公式に案内されている。一方式に絞ることで、接続の保存・検証・画面を最小にできる。

## 範囲と例外

運用者が自分のデプロイで自分のトークンを使う場合に適用する。Anthropic は、第三者の開発者が自分のプロダクトで Claude.ai ログインを提供することや、利用者の資格情報を収集・保管・仲介することを認めていない。Tailos を他の利用者に提供する段階では、この判断を見直して API キー接続を用意する。

- トークンは有効期間 1 年で、モデル呼び出しにだけ使え、更新できない。Tailos はトークンを更新しない。
- 保管は ChatGPT 接続と同じ暗号化ストアを使い、保存後に値を応答へ返さない。
- 保存時は形式だけを確かめる。有効かどうかは最初の Run で分かる。
- 保存日時を記録し、期限が近づいたら接続画面で知らせる。

## 選択肢と影響

API キーは Anthropic が第三者のプロダクトに認めている方式だが、従量課金になる。両方に対応すると、接続の種類ごとに保存・検証・表示が増える。

長期 OAuth トークンは Run をまたいで同じ値なので、漏れた場合の影響は ChatGPT 接続の短命なアクセストークンより大きい。Runner 内のプロキシで本物の値を付け替えて Agent のプロセスへ渡さない対策は、API キーでは組めるが、OAuth トークンでは Claude Code 自身のリクエストを模倣することになるため採れない。Agent が実行するコマンドからトークンを読めないようにする対策は、隔離と環境変数の除去に依存する。

## 再検討条件

Tailos を運用者以外に提供するとき。Anthropic がトークンの扱いに関する案内を変えたとき。
