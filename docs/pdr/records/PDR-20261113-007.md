# 通知レコードから重複値と将来用カラムを削減する

## 決定

PR #50 の issue_notifications から kind・session_id・target・applied_state を削除する。Run から取得できるセッション・送信先は参照し、反映判定は version / applied_version を使う。現在 1 種類の通知は run_id で一意にし、kind は必要になってから追加する。

## 理由

導出可能な値の二重管理と、未使用・将来用の状態を減らすため。通知種別の将来の拡張だけを理由に現時点の構造を複雑にしない。

## 範囲と例外

今回の Issue 受付・終了コメントに関する判断。将来複数種の通知が必要なら、新しい判断として再検討できる。

## 選択肢と影響

送信先の不変スナップショットが必要になる場合は、単純な重複削減ではなく、その要件を改めて議論する。
