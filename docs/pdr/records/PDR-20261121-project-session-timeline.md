# 会話内の実行タイムラインと展開できる履歴をデザインシステムに沿って表示する

## 決定

Project のセッション画面に、Agent の進捗報告とツール呼び出しを会話の流れで表示する。実行中は履歴を開き、コマンド・Web 検索・ツールの開始から完了まで同じ Item を更新する。完了した Run は `Worked for …` 等から履歴を開閉でき、コマンドの入力・出力・終了コード・所要時間を確認できる。最終回答は履歴の外に表示し、同じ回答を進捗として重複表示しない。

背景・文字・補助文字・枠線・失敗色、Geist と monospace、角丸・余白は既存の Tailos のセマンティックトークンを使う。アイコンは Tabler、操作は既存の共通部品とアクセシブルな開閉を使い、デザインシステムの文書に表示規則を追加する。Run の実行履歴の開閉アイコンは、`Worked for …` などのラベルの右隣に 6px 空けて配置する。進捗を示すために新しい色や推測の完了率を導入しない。

サーバーで会話・タイムラインを同じ D1 スナップショットから取得し、一覧の初回ページとは並列に取得する。取得済み内容はライブ接続の確立を待たずに描画する。ツール本文は展開時だけ取得し、過去の Item は 100 件単位で追加取得する。D1 に含む短い本文は JSON エスケープ後の UTF-8 で 8 KiB 以下とし、超える本文は切り捨てず展開時の取得に回す。JSON 集約の行サイズも抑えながら、診断の全本文や無制限の履歴を初期応答へ含めない。

接続中・再接続中・認証失効と、Agent の実行状態を分ける。欠落・未収集・本文失効も明示し、正常終了から完全な履歴を推測しない。末尾を見ている間だけ自動追従し、過去を読んでいる場合は新着への移動操作を出す。

## 理由

実行履歴のラベルと開閉操作がひとまとまりに見えるようにする。

会話の進捗と実行内容をその場で把握し、完了後も根拠を確認できるようにする。折りたたまれた履歴と独立した最終回答により、長いツール出力が会話全体を占有するのを防ぐ。既存デザインシステムを使うとホーム・セッション・管理画面で操作感と視覚的な階層が揃う。

## 範囲と例外

Project 付きの詳細は所有者と保存済み Project ID の両方を照合する。削除済み Project の履歴閲覧を維持する。Project を持たない従来 URL でもタイムラインを閲覧できる。入力欄の送信は引き続き無効であり、モデル選択だけで Run を開始しない。Figma のファイルは読み取り専用を維持する。

最初の段階では短い進捗の完成・検査後に配信し、コマンド出力は完了後に表示する。文字単位の streaming、内部の推論、実行中の追加指示や中断は今回の UI に追加しない。失われた過去の通知は復元したと扱わない。
