# 判断の説明は PDR 本文で完結させ、チャットを保存しない

## 決定

PDR 本文に、判断・理由・適用範囲と必要な前提を記載する。別の会話や資料を読まなければ判断を理解・評価できない状態を避ける。`sources` と `approval` のメタデータや、参照だけを置く根拠の章は設けない。チャット本文・抜粋・会話ログ・承認リンクは PDR や付属ファイルへ保存しない。

## 理由

意思決定の妥当性は、課題・制約・選択肢・影響の説明によって評価できる必要がある。発言へのリンクや「指示されたから」だけでは選択の理由が伝わらない。説明を PDR に集約すれば、Agent と人間が追加資料の探索に時間やトークンを使わず判断できる。会話を保存しないことで、判断に不要な秘密情報・個人情報・周辺の文脈がリポジトリへ持ち込まれるリスクも減らせる。

## 範囲と例外

本文、メタデータ、検索索引の元データ、付属ファイル、Agent 向けルールに適用する。人間との合意は引き続き採択前に行い、状態・日付・決定者の識別子を記録する。技術資料や実装箇所への補助的なリンクは利用できるが、判断を理解するための必読資料にはしない。由来が未確認の既存挙動は、その不足を本文に明示して `unverified` のまま残し、説明を捏造しない。

## 選択肢と影響

会話への参照を保存する方式では、参照先の消失・権限不足・余計な情報の保存に依存する。本文への要約には記述の手間があるが、意思決定に必要な内容を絞り、採択前の議論とレビューで説明の不足を確かめる。
