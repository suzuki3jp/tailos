# Issue 通知は Run と独立した永続送信状態で回収する

## 決定

Issue コメント通知は Run と独立した永続送信状態として扱い、別テーブルに保存する。Run の受付と同じ保存処理で通知待ちを残し、Run 終了後も通知だけを回収・再試行できるようにする。

## 理由

Run 作成直後の停止や GitHub の障害で通知が失われるのを防ぐため。Run の実行状態と、GitHub コメントへ反映できたかは別の状態であり、waitUntil の実行だけでは停止後の回収を保証できない。

## 範囲と例外

PR #50 の受付・終了通知の設計。外部への通知送信の失敗で実装・PR 作成を止めない。DB への受付と通知登録の原子性は必要であり、保存自体の失敗まで独立するという意味ではない。

## 選択肢と影響

Run にすべての通知用カラムを追加する案より、通知固有のコメント ID・リース・再試行の責務を分ける。
