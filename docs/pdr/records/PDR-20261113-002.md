# プロダクト判断は人間の合意と根拠を残して実装へ渡す

## 決定

ユーザー体験・既定値・上限・待機時間・失敗時の挙動など、選択に意味のある判断は小さくても記録する。新しい判断が必要なら Agent が選択肢・推奨案・影響を提示し、人間と合意してから依存する実装に進む。既に明確な指示がある場合は、判断・理由・範囲を本文に記録し、同じ承認を取り直さない。

## 理由

高速開発の中で、Agent の裁量による実装が由来不明の仕様として定着するのを防ぐため。採択済み判断、提案、観測、不採用、置き換え済みの判断を区別する必要がある。

## 範囲と例外

機械的なリネームや挙動を維持する内部整理まで新しい承認を必須にしない。コードレビューの LGTM はプロダクト判断への人間承認とは別。CI は形式と整合性を検証するが、人間の意思を認証しない。ユーザーの新しい明示指示が既存 PDR と異なる場合は変更点を示し、変更後の判断・理由・範囲を PDR に記録する。

## 選択肢と影響

事後に実装を正当化する記録だけでは、実装前の議論を確保できない。根拠不明の値にもっともらしい理由を補うと、誤った前提が再利用される。判断を変更するときは後継 PDR を作り、元の理由を履歴に残す。
