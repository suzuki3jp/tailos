# JSX Best Practices

- コンポーネントは関数として定義し、なるべく純粋に保つ。
- コンポーネントは一つの責務に絞り、読みやすい大きさに保つ。
- 複数の画面で同じ責務を担う処理は、既存のコンポーネントやヘルパーを再利用できるか確認する。
- Hono JSX では、データ取得や認証・認可をルートやサーバー側の処理に置き、画面に必要な値だけをコンポーネントに渡す。
- 接続画面を変更する場合は、待機中、接続完了、失敗の状態と、再試行できるかどうかを確認する。ブラウザや画面のログに渡す値は表示と接続に必要なものに絞る。
- React を使う箇所では関数コンポーネントを使う。Web のデータ取得と初期表示は [データ取得と Loading の設計](../../fsd/references/fetch-and-loading.md) に従い、サーバーの取得・prefetch を先に検討する。既存の client-side fetch をそのまま採用理由にしない。
- `"use client"` が必要な対話操作・ブラウザ API などに局所化されているか確認する。Loading の有無は情報の重要度と実際の待ち時間から評価し、初期表示では `loading.tsx` / `Suspense` を優先する。`useEffect` の取得を追加する場合は必要な理由、再実行・キャンセルと初期データの有無も確認する。
