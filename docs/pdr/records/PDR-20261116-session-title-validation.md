# 生成タイトルを独立して検証し最初の正常値を一度だけ保存する

## 決定

Agent には会話の主な言語で目的・内容を簡潔に表すタイトルを求める。受理する `sessionTitle` は文字列とし、前後の空白を取り除いた後に 1〜100 UTF-16 コード単位で、改行・制御文字を含まない値とする。言語そのものは機械的な拒否条件にしない。長すぎる値は切り詰めず不正として扱う。

前後の空白は JavaScript の `String.prototype.trim()` が取り除く文字集合とする。取り除いた後の文字列に Unicode 一般カテゴリ Cc（U+0000–U+001F、U+007F–U+009F）、行区切り U+2028、段落区切り U+2029 があれば不正とする。書式文字の一般カテゴリ Cf は、この改行・制御文字の拒否条件には含めない。Runner と API は共有契約で同じ検証を使う。

ランタイムに渡す構造化応答の JSON Schema は `sessionTitle` の不備だけで応答全体を拒否しない形とし、Runner でタイトルを他の項目から独立して検証する。欠損、null、型違い、空文字、長さ超過などはタイトルなしとして扱い、reply・headline・計画結果の既存の検証は維持する。既存 Runner のタイトルなし応答も受理する。既存の秘密情報除去で内容が変わるタイトルは採用しない。

保存時は生成タイトルの確定状態を Session に持たせ、未確定の場合だけタイトルと確定状態を同じ SQL 更新で変更する。再送・並行実行でも最初に保存できた正常値を維持する。要約の再試行では最初に得た正常なタイトルを保持し、後続の要約だけで置き換えない。

実装成果が公開待ちになる場合は、受理した応答のタイトルを公開チェックポイントと同じ永続化で Session に反映し、チェックポイントにも引き継ぐ。PR 公開失敗や復旧後もタイトルを維持する。計画・変更なしの応答は正常な応答を API が受理して保存する時点で反映する。タイトルの確定だけでは会話の活動時刻を進めない。

## 理由

生成タイトルを API が保存・返却するメタデータとして扱い、改行・制御文字を含まない文字列に制限する。100 コード単位を上限として保存量を制御しつつ、日本語の目的も記述できるようにする。言語の機械判定や黙った切り詰めは誤判定と意味の欠落を招くため行わない。タイトルを独立に検証すれば、補助情報の不備で本来の成果を失わない。

生成タイトルの確定状態と値を原子的に保存すれば、一度だけという約束を再送や公開復旧の経路でも維持できる。公開前に保存することで PR 公開の成否を会話名の確定条件にしない。

JavaScript の既存の空白除去と Unicode のカテゴリで文字集合を明記し、実装間の判定のずれを避ける。書式文字まで一律に拒否すると、絵文字の結合に使う ZWJ や言語によって必要な文字も拒否するため、改行・制御文字とは区別する。

## 範囲と例外

API と Runner の応答契約、タイトルの検証・永続化だけの規則とする。GitHub Issue の初期タイトルは Issue の文字列を保存し、この長さ制限で切り詰めない。タイトル専用の Agent 呼び出しや改名 API は追加しない。ランタイムが生成する JSON 全体の破損は、タイトルだけの不備と見なさない。

[アカウントのセッション一覧の判断](PDR-20261116-session-list.md) の未決事項のうち、生成タイトルの長さ・言語・空白、独立した検証、原子的・冪等な保存と公開復旧への引き継ぎを確定する。

## 選択肢と影響

タイトルを応答全体の厳格な必須文字列にすると、タイトルだけの不備も本来の処理を失敗させる。上限なしでは保存量や API のレスポンス量を制御できない。正常な値を受理するまでは初期タイトルを維持し、後続応答で再試行する。
