# 実行する Agent は Project の config で選び、未指定は Codex にする

## 決定

Issue から起動する Run の Agent は、Project の config の `agent`（`codex` または `claude`）で決める。未指定の Project は `codex` で実行する。

## 理由

Agent が二種類になると、起動のたびにどちらを使うかを決める必要がある。トリガーのラベルや対象リポジトリなどの起動ルールは既に Project の config で管理しているので、同じ場所に置けば設定の所在が一つにまとまる。未指定を Codex にすることで、既存の Project は設定を変えずにこれまでと同じ挙動を保つ。

## 範囲と例外

GitHub の Issue から始まる Run に適用する。選んだ Agent は Run の実行設定に記録し、Run の途中や再試行で変えない。画面の Agent 表示名はこの記録から出す。

選んだ Agent の接続がない場合は、もう一方の Agent に切り替えず、接続がないときの既存の失敗として扱う。

Run や Session ごとに Agent を選ぶ操作、モデルや effort の指定は、この判断の対象にしない。

## 選択肢と影響

ラベルで Agent を選ぶ方式は Issue ごとに切り替えられるが、ラベルの種類と起動判定が増える。config で決める方式では、同じ Project の Issue はすべて同じ Agent で実行される。
