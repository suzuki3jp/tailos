# ディレクトリ構成

Tailos の設計上の責務を示す。各 PR の対象フェーズと実装済みの構成に合わせて確認する。

| 配置 | 責務 |
| --- | --- |
| `apps/api` | GitHub Webhook の受付、Run の進行と永続化、コンテナ制御、プロバイダ認証、PR 作成。D1 のスキーマとマイグレーションもここに置く。 |
| `apps/runner` | 内部 HTTP でジョブを受け取り、作業ディレクトリで Agent を実行する。Agent 固有の処理は Adapter に置く。 |
| `packages/core` | API と Runner が共有するジョブ、イベント、結果の型とスキーマ。 |

## レビュー観点

- **起動の境界。** API のトリガー実装で署名、起動者、対象を確認してから、共通の実行要求に変換する。重複配送や同時起動時に同じ Run を二重作成しないことを確認する。
- **実行の境界。** Runner の Agent Adapter に Codex 固有の起動、入力、イベント、結果の変換を閉じる。API と Runner は共有契約を使い、共有契約の依存先はプラットフォームに依存しない型やスキーマに絞る。
- **状態と復旧。** D1 を Run の状態の正本とする。状態遷移の条件、タイムアウト、途中失敗後の再試行で既存のコンテナ、ブランチ、PR を再利用できるかを確認する。
- **認証の境界。** プロバイダの接続と資格情報の更新は API で管理する。Runner へ渡す資格情報の対象リポジトリ、権限、有効期限と、ログや成果物への露出を確認する。
