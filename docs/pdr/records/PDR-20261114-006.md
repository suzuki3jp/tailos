# Claude の認証が拒否されても接続は自動で無効にしない

## 決定

Run の実行中に Claude の認証が拒否された場合は、その Run を Agent の失敗として終える。保存済みの接続は変更せず、接続画面の状態も接続済みのままにする。

## 理由

Claude の長期 OAuth トークンは更新できず、Tailos は保存時に有効性を確かめられない。失効や期限切れは Run の失敗として初めて現れる。

接続を自動で無効にするには、Runner が認証の拒否を他の失敗と確実に区別して API に返す必要がある。区別を誤ると、一時的な障害で有効な接続を消し、利用者にトークンの再発行を求めることになる。最初の実装では失敗の種類を区別しないため、接続には手を付けない。原因は実行記録から調べられる。

## 範囲と例外

Claude 接続に適用する。ChatGPT 接続は、トークン更新で再認証が必要と判定された時点で接続を失敗状態にする従来の挙動を保つ。

## 選択肢と影響

トークンが失効している間は、起動した Run がすべて同じ理由で失敗し、接続画面からは原因が分からない。利用者は実行記録を見て、接続を解除して貼り直す必要がある。保存日時から期限が近いことを知らせる表示（`agent.claude.authentication`）が、期限切れについての手掛かりになる。

## 再検討条件

Runner が認証の拒否を独立した失敗として返せるようになったとき。
