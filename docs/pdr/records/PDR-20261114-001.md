# 計画会話は必須入力を保持し古い履歴をバイト予算内で渡す

## 決定

最新の成功計画と以後の受理入力を必須とし、古い履歴をバイト予算内で追加して省略 ID を明示する案は、今回採用しない。[PDR-20261113-012](PDR-20261113-012.md) の全文送信を当面維持する。

## 理由

全履歴の送信は日本語の長い返信が数回蓄積すると Runner の 32 KiB 上限に達し、同じ履歴を含む再実行でも失敗する。この制約は残るが、暫定的な履歴選別の実装を追加せず、将来は対象 Issue の識別情報から Agent が GitHub に問い合わせる方式へ移行する。[PDR-20261114-002](PDR-20261114-002.md) にその方針を記録する。

## 範囲と例外

履歴省略案の不採用を記録する。Issue のタイトル・本文を最新計画として自動更新する案も今回導入しない。PR #57 の Webhook 応答と診断理由の修正には影響しない。
