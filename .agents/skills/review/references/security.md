# セキュリティ

変更に関係する経路を、入力元から副作用やデータの公開先までたどる。Agent が指示に従わない場合や、リポジトリ内のコードが意図的に悪い動作をする場合も考え、Worker・DO、Runner、Agent の子プロセス、外部サービスのどこで制約が効くかを実装とデプロイ設定で確認する。

## 起動と権限

- GitHub Webhook は生のリクエスト本文で署名を検証したうえで、起動者の権限、対象リポジトリとインストール、イベント種別とラベルを照合する。正規の配送でも、未許可の起動や再送による二重実行を防げるか確認する。
- Run の照会、Runner への内部リクエスト、トークン更新、成果物の取得では、呼び出し元と対象 Run・プロジェクト・接続の対応を検証する。URL や本文に別の ID を指定して、他の Run を操作できる経路を探す。

## 外部入力と実行の分離

- Issue・PR の本文、チェックアウトしたファイルやエージェント向け指示、ツール出力を通じてプロンプトインジェクションが起こりうる。起動先、権限、送信先、書き込み先は信頼できる設定と確定済みの Run から決め、モデルが指定するツール引数も実行側で照合する。
- リポジトリのスクリプト、Git フック、依存関係のインストールやテストもコード実行として扱う。リポジトリ名、ref、パスなどをシェルへ渡す箇所では引数として分けて扱い、オプション注入やパスの逸脱を確認する。
- 本番で有効な sandbox 設定、ファイルの読み書き範囲、マウント、環境変数、内部ポートを確認する。子プロセスからシンボリックリンクや共有領域を経由してホスト、制御用 API、別の Run に届かないかを調べる。sandbox の初期化に失敗した経路や再試行で制限が緩まないことも確認する。
- 終了・取消・タイムアウトで子プロセスを止め、作業領域やキャッシュに残ったコード・認証情報を別の Run から読めないようにする。同時実行数、実行時間、ログや成果物のサイズなど、変更箇所で消費する資源に上限があるか確認する。

## 認証情報と通信

- GitHub App の秘密鍵や長期の認証情報は信頼できる API 側で扱う。Runner に渡すトークンや更新用リースは用途・対象・権限・期限を絞り、Agent が参照できる環境変数、ファイル、プロセス引数までたどって実際の露出を確認する。
- 外向き通信は Agent の指示と独立した層で制限する。任意 URL、リダイレクト、直接 IP、別ポートを使って、想定外の宛先や内部サービスへ到達できないか確認する。許可したホストでも、別リポジトリへの書き込みやデータの持ち出しが可能かを確認する。プロキシが資格情報を付ける場合は、送信先と操作の範囲も検証する。
- モデルや外部ツールへ渡すデータは、その Run で許可された範囲に絞る。機密情報がプロンプト、コマンド出力、エラー、R2 のログや成果物に流れる経路を確認する。保存前に機密情報を除き、閲覧やダウンロードも対象 Run の権限で制御する。

## GitHub と CI への公開

- push 先を対象リポジトリの作業ブランチに限定し、既定ブランチへの直接 push やマージを保護ルールで防げるか確認する。PR の宛先は確定した Run から選ぶ。
- Agent が生成した差分や変更されたワークフローが、秘密情報や書き込み権限を持つ CI で自動実行される経路を確認する。`pull_request_target` などの権限付きワークフローから未信頼の head、スクリプト、成果物を実行する変更を見逃さない。
- PR 本文、レビューコメント、添付物に認証情報や非公開データが含まれないか確認する。ログから追える情報は Run の識別子、許可・拒否した操作とその結果など、原因調査に必要なものに絞る。

## レビュー時の検証

- PR のコードや依存関係を実行する場合は、秘密情報、書き込み用の GitHub 認証情報、別 Run のデータから隔離された検証環境を使う。用意できない場合は CI と静的確認を使い、手元で実行していないことを記録する。
- 変更に合う拒否ケースを確認する。たとえば権限のない起動、別 Run の ID、許可外への通信、期限切れのリースで、後続の副作用が起きないことを確かめる。可能ならダミーの認証情報や隔離されたテストで検証する。
- 指摘には入力を制御できる主体、抜ける境界、到達先と影響、実際の制約がどこで効くかを示す。未確認のデプロイ設定は確認済みの事実と区別し、秘密情報の実値は掲載しない。

実行環境の設定を確認する際の資料は [OpenAI の Sandbox security](https://developers.openai.com/api/docs/guides/agents-api/environments/security)、[Cloudflare Containers の外向き通信](https://developers.cloudflare.com/containers/configuration/outbound-traffic/)、[GitHub Actions の権限付き PR ワークフロー](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target)。
