# TypeScript Best Practices

- 型は扱う値や状態を表せるよう厳密にする。`any` の使用を避ける。
- 共有する状態や設定値は、責務を持つモジュールで定義する。
- 固定値の集合は、既存の規約に沿って文字列リテラルの union や `as const` のオブジェクトで表せるか検討する。

## `as` アサーションの使用

- `as SomeType` によるキャストは可能な限り避ける。
- やむを得ず使用する場合は、安全性を保証する条件をコメントで説明する。
- `as string` や `as unknown as T` が、検証していない値や食い違った型を通していないか確認する。
- 型ガード関数（`(x): x is T => ...`）や Valibot の実行時バリデーションに置き換えられないか検討する。

## Branded Types と層境界

- Branded Type を使う箇所では、外部入力を受け取る境界で値を検証して型を確定し、内部では確定した型を受け渡す。
- ID の形式検証に加えて、認証済みの主体がそのリソースを操作できるかを認可の境界で確認する。
- 内部で同じ ID を繰り返し変換している場合は、受け取り側の型が必要な情報を保持しているか見直す。

## 共有契約

- Webhook、API と Runner の通信、D1 に保存した JSON は、読み込む境界で実行時に検証する。
- 共有するジョブ、イベント、結果のスキーマは `packages/core` に置く。保存形式を変更する場合は既存のバージョンを読み取れることを確認する。
