# 実装の要約失敗時の成果保持と時間配分は個別承認が未確認

## 決定

観測: PR #54 の 773b2c2 では、実装の要約再要求を残り 60 秒以上で開始し、待機を最大 30 秒とし、公開用に 30 秒を見込む。要約不能時は完成したコードと最初の headline を維持し、案内文で公開を続ける。計画・checkout なしでは回数超過や時間不足を失敗として扱う。これらの具体的な設定の人間による個別承認は未確認。

## 理由

返答を整える間に Run の期限を迎え、完了した実装まで失うというレビュー指摘への対応として Agent が導入した。技術的な説明とコードの LGTM は得られたが、それをプロダクト上の人間承認と同一視しない。

## 範囲と例外

PR #54 の記載コミットに関する観測。main の f6cc56f に反映済みで、`apps/runner/src/codex-agent.ts` で残り 60 秒の開始条件、最大 30 秒の待機、公開用 30 秒の確保、要約不能時の成果保持を確認した。以後の版の実装状況は別途確認する。実装の存在は、これらの設定への人間の個別承認を意味しない。採択済みの最大 2 回の再要求方針とは分けて扱う。

## 選択肢と影響

具体的な時間配分や、要約不能時に本文を案内文へ置き換える体験は、人間と再確認する必要がある。

## 未決事項

人間の承認・選定根拠を確認する。確認できるまでは採択済みの方針として適用しない。
