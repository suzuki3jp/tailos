# ディレクトリ構成

配置や依存方向を確認するには `pnpm lint` を実行する。レビューでは変更する概念の所有者と実際の呼び出し元を特定し、次の観点で責務や契約を確認する。

## レビュー観点

- **起動の境界。** API のトリガー実装で署名、起動者、対象を確認してから、共通の実行要求に変換する。重複配送や同時起動時に同じ Run を二重作成しないことを確認する。
- **実行の境界。** Runner の Agent Adapter にプロバイダー固有の起動、入力、イベント、結果の変換を閉じる。API と Runner で共有する契約は、特定の実行環境やプロバイダーの SDK を必要とせずに読める型とスキーマにする。
- **状態と復旧。** D1 に保存する Run の状態と、コンテナ内の進行や Web のキャッシュを区別する。変更した書き込みから再読み込みまでをたどり、重複配送・再試行・途中停止でも状態の所有者が競合や二重処理を防げるかを確認する。
- **互換性。** 公開型、永続化する値、旧データの読み取りを変える場合は、実際の利用者と既存データの形式を確認する。共有する規則は所有するモジュールに集約し、互換処理はその利用者か契約を説明できるものを残す。
- **認証の境界。** プロバイダの接続と資格情報の更新は API で管理する。Runner へ渡す資格情報の対象リポジトリ、権限、有効期限と、ログや成果物への露出を確認する。
