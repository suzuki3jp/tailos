# Session の会話本文を Markdown で表示する

## 決定

Project の Session 画面と従来の Session 詳細で、ユーザー、Agent、GitHub 起点の保存済みメッセージ本文を同じ Markdown 規則で表示する。

- 初回は見出し、段落、改行、強調、順序付き・順序なしのリストと入れ子、リンク、引用、区切り線、インラインコード、コードブロックを扱う。段落とリスト項目内の通常の改行も表示に反映する。
- 本文は Geist 16px、見出しの最大サイズは 18px・太さ 600、本文の強調は太さ 500 とする。順序なしリストの一階層目は塗りつぶし、二階層目は枠線の四角マーカーを使う。リンクは常時下線付きで、通常の本文では青紫、色付きの吹き出しでは本文色を使う。
- 引用は左罫線、インラインコードは等幅と薄い背景、コードブロックは薄い背景と角丸を使う。長いコード行はコード枠内で横スクロールできるようにする。
- Shiki は言語名が明示されているフェンス付きコードブロックを色分けする。インラインコード、言語名のないブロック、対象外言語のブロックは等幅表示とする。ハイライトの読み込み中や処理に失敗した場合も、コード本文を等幅で表示する。

## 理由

会話に表示する Agent の回答には、箇条書きやコード、GitHub へのリンクが含まれる。見出しと階層を読み取れ、コードの空白を保てる表示にする。Figma の見出しと本文は会話内で近いサイズに収まり、箇条書きの深さは四角マーカーの塗りと字下げで見分けられる。色付きの吹き出しで使うリンク色は、下線と本文色を組み合わせてコントラストを確保する。

保存済みのプレーンテキストには改行だけで行を分けた本文もあるため、表示で改行を保持する。保存済みの本文をそのまま読み込めるようにし、保存形式には Markdown 用の属性を追加しない。

インラインコードには CommonMark の言語指定がなく、Codex と Claude Code の実際の返信ではコマンド、ファイル名、識別子が混在していた。言語名のあるブロックに色分けを適用すると、作者が指定した文法で読める。ハイライトを待つ間もメッセージ全体を読むことができる。

## 範囲と例外

- 対象は保存済みメッセージの本文とする。実行中の進捗、ツール出力、ジョブ情報、送信前の入力欄は適用範囲外とする。最終回答を実行履歴の外に表示する既存の取り決めを引き継ぐ。[Session 詳細の表示](PDR-20261124-session-detail-send.md)
- リンク先は絶対 `https` / `http` URL を有効にする。対象外の URL はラベルを本文に表示する。HTML はテキストとして表示し、画像は代替テキストを表示する。メッセージを開くだけで画像の送信先にブラウザーが接続することを防ぐ。
- GFM の表、タスクリスト、取り消し線、裸の URL のリンク化、脚注と、数式・Mermaid は後続候補とする。

## 選択肢と影響

- GFM の表やタスクリストも初回から有効にすると、GitHub 由来の書式を広く表示できる。表の横幅やチェックボックスの表示も初回の設計・検証に含まれるため、今回は Figma で確認できた表現とコードの表示を先に扱う。
- Agent の回答だけに適用すると、入力した文字が書式に解釈される影響を限定できる。全投稿者への適用では、送信者を問わず段落やリストを同じ書式で読める。既存の本文も解釈されるため、記号をそのまま表示するにはエスケープやコード記法を使う。

Tailos の新しい順に 40 セッションを調べ、実行のプロバイダーを Codex と確認できた保存済み返信 34 件のうち 26 件にインラインコードがあった。フェンス付きブロックは 0 件だった。別途、同じリポジトリのローカル Claude Code 履歴で、ツール呼び出しを除いた応答完了時のテキスト 118 件を調べた。102 件にインラインコードがあり、5 件にフェンス付きブロックがあった。5 ブロックのうち 2 件は `bash`、3 件は言語指定なしだった。Claude Code の集計は対話 CLI の履歴に基づく。Tailos の Agent SDK 経由の返信に対する出現頻度は未確認とする。
